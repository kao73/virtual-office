# CLAUDE.md

Контекст для Claude Code-сессий в этом репозитории.

## Что это

Виртуальный IT-офис — самостоятельный проект-шаблон: команда AI-агентов, ведущая
разработку проектов-клиентов через конвейер с фиксированными гейтами контроля владельца.
Упаковка — плагин Claude Code (репозиторий = плагин + маркетплейс).

## Источник истины

**Перед любой работой прочитай `docs/concept.md`** — конституцию офиса: цель и роли
человека (§1), журнал решений (§2), архитектуру «доска — и есть офис» (§3), контракты
ролей (§4), жизненный цикл карточки и гейты (§5), профиль клиента и адаптер трекера (§6),
способности и раннеры (§7), приёмку AI-QA (§8), отказы (§9), метрики (§10),
упаковку (§11), дорожную карту (§12).

Конституция — живой документ: правки только через явное решение с записью в журнал
решений (§2). Молча менять законы офиса нельзя.

**Объём первой версии — в `docs/v1-scope.md`** (введён решением Р-28). Конституция
описывает полный замысел; что из него делается сейчас, в каком порядке и что отложено —
только там. Эмпирика живых API трекеров — в `docs/providers/`.

- Концепт зафиксирован владельцем 2026-07-27 (Р-01…Р-27); ревизия 2026-08-14
  сократила объём первой версии (Р-28…Р-35).
- Этап 0 «Фундамент» реализован 2026-07-28: репозиторий — устанавливаемый плагин
  и собственный маркетплейс (спека и план — в `docs/specs/` и `docs/plans/`,
  версии — в `CHANGELOG.md`). Установка проверена на демо-клиенте
  `~/IdeaProjects/office-demo`; clens не трогаем до первой роли.
- **Порядок работ для v1 задаёт `docs/v1-scope.md` (лестница шагов), а не §12
  концепта** (Р-31). Шаг закрывается не демо и не зелёными тестами, а неделей личной
  эксплуатации владельцем; потолок шага — порядка восьми задач.
- Реализация шва — на Go (Р-29). Первая попытка на Python заморожена тегом
  `archive/python-adapter`, её спеки и планы лежат в `superseded/`.
- Пока трекер один (Jira) — никаких интерфейсов провайдеров, реестров и фабрик:
  абстракция трекера живёт в конфиге состояний, а не в коде (Р-30).
- Каждый шаг: брейншторм (при развилках) → дизайн-док в `docs/specs/`
  (`YYYY-MM-DD-<topic>-design.md`) → план → реализация.
- Язык документов — русский; идентификаторы, термины, ключи конфигов — английские.

## Клиент №1

clens — `~/IdeaProjects/clens`. Его legacy-прототип офисного цикла:
`.autodev/kanban.config.json` + скиллы autodev-* (импортируются визардом `office-init`

## Правила репозитория

- Ничего не реализовывать вперёд лестницы шагов (`docs/v1-scope.md`); YAGNI.
- Если генерируется кода больше, чем владелец успевает прочитать, — остановка
  и доклад, а не «допишу, потом разберётся» (Р-31).
- Секретов в репозитории и профилях клиентов нет никогда.
- Список необратимых операций (концепт §9) не ослабляется ни при каких обстоятельствах.
