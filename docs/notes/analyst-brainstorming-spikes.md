# Спайки: analyst + Superpowers `brainstorming`/`writing-plans`

Два экспериментальных прогона, предшествовавших изменению
`analyst-brainstorming-skill` (`docs/openspec/changes/archive/2026-08-30-analyst-brainstorming-skill/`).
Ветки `experiment/skill-question-spike` и `experiment/writing-plans-handoff-spike`
существуют только локально на машине владельца и не запушены в `origin` —
этот файл делает их выводы проверяемыми без доступа к самим веткам.

## `experiment/skill-question-spike` (три прогона, ~$0.72)

Подключение Superpowers `brainstorming` и явный его вызов безопасны для
headless-исполнения: когда собственная инструкция скилла требует одобрения
человека, а интерактивного инструмента для вопроса у прогона нет
(`AskUserQuestion` отсутствует в `--tools`), агент падает в родной для
офиса протокол `needs_human`/типизированный вопрос — без зависания и без
выдумывания согласия. На повторном прогоне, после ответа человека, агент
распознаёт уже закоммиченную работу как достаточное состояние и не
вызывает скилл заново.

## `experiment/writing-plans-handoff-spike` (один прогон, $0.43, 22 шага)

Подключение `writing-plans` вместе с `brainstorming` и приглашение полного
architectural-пути — включая обязательный шаг `writing-plans` «Execution
Handoff», который спрашивает, каким из двух подходов выполнять план —
показало то же самое поведение при явной инструкции: агент, которому
прямо сказано никогда не отвечать на этот вопрос и не вызывать ни один из
названных под-скиллов, классифицировал задачу как architectural,
прогнал `brainstorming` до написанного спека, вызвал `writing-plans` и
чисто остановился, как только план был сохранён — без зависания, без
попытки вызвать неподключённый скилл, без выдуманного ответа. Ни один из
скиллов не редактировался и не обходился — оба дошли до своего
естественного, неизменённого завершения.
