## Что выяснилось первым и меняет остальное

**`curl … | sh` — не конвенция, а исключение.** Из двенадцати README такую
команду показывает ровно один — goose
(`curl -fsSL …/download_cli.sh | bash`,
https://raw.githubusercontent.com/block/goose/main/README.md, строка 38).
Остальные показывают пакетные менеджеры (`brew`, `npm`, `pip`, `go install`,
`pacman`, `winget`) или просто ссылаются на страницу установки. Наш `install.sh`
с однострочником из релиза — редкая форма, и вокруг неё принято класть
альтернативу, а не единственный путь.

**Раздел «Ограничения» или «Статус» — тоже не конвенция.** Заголовок такого
смысла нашёлся в одном README из двенадцати: `## Known Issues` у k9s
(https://raw.githubusercontent.com/derailed/k9s/master/README.md, строка 1481:
«This is still work in progress!»). Там, где зрелость всё-таки заявлена, это
короткая врезка или бэдж, и почти всегда — плохая новость: `status-beta` у
OpenHands (строка 14), `> [!warning]` «superseded by mini-swe-agent» у SWE-agent
(строки 19–24), «no longer actively maintained and is read-only» у continue
(строка 19). Спокойного раздела «вот чего мы не умеем» в выборке нет ни у кого.

**Половина «агентного» лагеря сама в переходном состоянии.** continue —
архивирован и доступен только на чтение по собственному README. SWE-agent
рекомендует вместо себя другой проект. `block/goose` отвечает HTTP 301 на
`aaif-goose/goose` (`gh api repos/block/goose` → `full_name: aaif-goose/goose`):
проект переехал в Agentic AI Foundation при Linux Foundation. Эти три README
стоит читать как документы конкретного момента, а не как образцы устойчивой
практики; Go-лагерь (k9s, lazygit, gitea, woodpecker, glow, dagger) в этом
смысле надёжнее.

**Наш репозиторий уже публичный, и опубликованный `master` уже несёт то, чего
нет в рабочей ветке.** `gh api repos/kao73/virtual-office` даёт
`private=false`, `license.spdx_id=MIT`, `has_issues=false`, `has_wiki=false`,
`description=null`, `topics=0`, релизов — ноль. На `origin/master` лежат
`LICENSE` (MIT, 1062 байта), `SECURITY.md`, `CODEOWNERS`, `.github/dependabot.yml`,
`.github/pull_request_template.md`, `.github/workflows/ci.yml` — коммит 68b0445
от 2026-09-18. Рабочая ветка `comet/office-dir-and-readme` этих девяти коммитов
не содержит (`git rev-list --left-right --count HEAD...origin/master` → `21 9`),
и её README в разделе «Статус и лицензия» утверждает: «Лицензии в репозитории
пока нет». Относительно того, что посетитель видит на GitHub прямо сейчас, это
неверно. Посетитель, к слову, видит и старый README на 649 строк — рез на 139
строк ещё не слит.

## Что действительно является конвенцией

Считаю конвенцией то, что делают 10–12 из 12.

**LICENSE есть у всех двенадцати** (`gh api repos/<repo> --jq .license.spdx_id`):
семь Apache-2.0, пять MIT. Это единственный файл без единого исключения в
выборке.

**Описание репозитория заполнено у всех двенадцати**, темы (topics) — у
одиннадцати (нет только у cline). Это поле видно в поиске GitHub раньше, чем
README.

**Документацию никто не держит в GitHub Wiki.** Ни один из двенадцати README не
ссылается на `github.com/…/wiki` (проверено grep по всем файлам). Флаг
`has_wiki=true` у семи из них — значение по умолчанию, а не признак
использования.

**Точка входа в документацию названа в README явно** — у всех двенадцати: либо
раздел `## Documentation`, либо бэдж-ссылка, либо строка в шапке.

**Шаблоны issue есть у одиннадцати из двенадцати** (нет только у dagger) — это
более распространённый артефакт, чем CONTRIBUTING (8/12), CODE_OF_CONDUCT (7/12)
и SECURITY (5/12). Дешёвый фильтр входящего потока оказывается востребованнее
документа о том, как контрибьютить.

**Одно предложение «что это» стоит в первых строках** — у всех двенадцати.
Формально это не всегда tagline под логотипом: у dagger первая же строка файла —
`## Dagger: a better way to ship`, и объяснение идёт сразу за ней
(https://raw.githubusercontent.com/dagger/dagger/main/README.md).

**Изображение до первого `##`** — у одиннадцати из двенадцати (исключение —
dagger, у которого изображений в README нет вообще). Логотипа или баннера нет
у трёх: dagger, gitea, goose (у goose — только текстовый `# goose` с курсивным
подзаголовком). Демонстрация работы (GIF, скринкаст, скриншоты) есть у семи:
lazygit (GIF `commit_and_push-compressed.gif`), glow, k9s (раздел
`## Screenshots`), woodpecker (`docs/woodpecker.png`), OpenHands
(`assets/screenshot/automation-preview.png`), aider (`assets/screencast.svg`),
gitea (20+ скриншотов в свёрнутом `<details>` в самом низу).

## Где два лагеря и что предсказывает лагерь

**Длина README: короткая (49–83) против длинной (235–1519).** Ходовое
объяснение — «есть сайт документации, значит README короткий» — выборкой
опровергается. Сайт есть у десяти из двенадцати, в том числе у cline (235) и
k9s (1519). Предсказывает лагерь не наличие сайта, а то, кому принадлежат
инструкции:

- README — единственный дом документации: glow (242 строки, каталога `docs/`
  в репозитории нет вообще) и lazygit (643 строки, `docs/*.md` в репозитории);
- README — витрина продукта: cline (235 строк, 13 разделов `##` — это тринадцать
  фич подряд, первый `##` только на 123-й строке, до него таблица из четырёх
  продуктов);
- сайт — единственный источник, README — обложка: dagger (49), goose (63),
  woodpecker (83), continue (63);
- k9s — отдельный случай: сайт k9scli.io реальный (разделы `/topics/install`,
  `/topics/config`, `/topics/plugins`), и при этом README на 1519 строк
  дублирует его. Это не образец, а долг: любое изменение надо вносить дважды.

**Где живут доки: внешний сайт (10/12), только репозиторий (lazygit), только
README (glow).** Причём «каталог `docs/` в репозитории» у большинства означает
исходник сайта, а не документацию для чтения с GitHub: у woodpecker и dagger там
Docusaurus, у SWE-agent — mkdocs, у goose каталог называется `documentation/`, у
aider сайт собирается из `aider/website` и публикуется по `CNAME` на aider.chat.
Плоский набор markdown-файлов, который читают прямо в репозитории, — это ровно
lazygit: `docs/Config.md`, `docs/Undoing.md`, `docs/Searching.md` и так далее,
плюс `docs/README.md` как индекс. То есть наша схема — редкая (1 из 12), но
живая, и работает у проекта с 82 тысячами звёзд.

**Установка: пакетные менеджеры против ссылки.** Длинный список менеджеров —
k9s (16 вариантов), lazygit (~20 подразделов, открывается бэджем Repology),
glow (~12). Голая ссылка без команды — woodpecker, SWE-agent, gitea (в README
gitea нет ни одной команды установки вообще). Предсказывает лагерь возраст и
наличие людей, которые ведут пакеты: у проектов 2016–2019 годов пакеты есть, у
молодых (dagger — только `brew`, aider — только `pip`, cline — только `npm`) их
нет, и они показывают один канонический способ.

**Бэджи: есть у десяти, нет у двух.** Ноль вхождений `img.shields.io` у cline
(68 тыс. звёзд) и dagger (16 тыс.). Значит, бэджи не обязательны даже при
большой аудитории. Ходовые типы: лицензия, статус CI, чат (Discord/Slack/Matrix),
версия релиза, ссылка на доки.

## Что не переносится

Практики, которые держатся на масштабе или на английском языке. Копировать их
при одном сопровождающем и русской документации нет смысла.

- **Отзывы пользователей.** У aider раздел `## Kind Words From Users` — 33 цитаты,
  примерно 39 строк из 180, то есть пятая часть README.
- **Спонсорские блоки выше логотипа.** У lazygit три рекламных блока (Warp,
  Tuple, Subble) стоят до логотипа и тэглайна; у k9s раздел `## Note...` с
  просьбой о спонсорстве — выше бэджей и скриншотов.
- **Счётчики масштаба как бэджи.** У aider в шапке «Installs 6.8M»,
  «Tokens/week 15B», «OpenRouter Ranking Top 20».
- **Бэджи чата.** Discord/Slack/Matrix предполагают, что в комнате кто-то есть.
- **Полный комплект CONTRIBUTING + CODE_OF_CONDUCT.** Восемь и семь из двенадцати
  соответственно, и даже крупные проекты (woodpecker, glow) выносят их на уровень
  организации, а не держат в репозитории. Оба документа описывают поток
  контрибьюторов, которого у нас нет.
- **Сайт документации на Docusaurus/mkdocs.** Это отдельный объект
  сопровождения: версии, сборка, деплой, CNAME.
- **Английский как язык README.** Все двенадцать англоязычны. Единственный
  проект с переводами — gitea: `README.zh-cn.md`, `README.zh-tw.md` и строка-
  переключатель прямо под заголовком (строка 12:
  `[繁體中文](./README.zh-tw.md) | [简体中文](./README.zh-cn.md)`). Обратной
  конфигурации — не-английский README как основной — в выборке нет ни одной, и
  это надо понимать трезво: конвенции выборки написаны для англоязычного
  читателя. Язык документации у нас решён и не пересматривается; переносима
  здесь только механика gitea — короткая ссылка на другой язык под заголовком —
  и то, что описание репозитория на GitHub всё равно читается в поиске.

## Чек-лист для нашего репозитория

Каждый пункт сформулирован так, чтобы на него можно было ответить «да» или
«нет», глядя на файлы. Состояние — на 2026-09-19; там, где ветка и
опубликованный `master` расходятся, это сказано отдельно.

1. **LICENSE лежит в корне той ветки, которую видит посетитель.** Частично:
   на `origin/master` — да (MIT, коммит 68b0445), в рабочей ветке
   `comet/office-dir-and-readme` файла нет. 12 из 12 эталонов имеют лицензию.
2. **README не противоречит лицензии.** Нет: `README.md`, раздел «Статус и
   лицензия», утверждает «Лицензии в репозитории пока нет» — на опубликованном
   `master` она есть. Строку надо убрать или переписать до слияния ветки.
3. **Описание репозитория (About) заполнено.** Нет: `description=null`.
   12 из 12 эталонов заполняют.
4. **Темы (topics) проставлены.** Нет: `topics=0`. 11 из 12 эталонов имеют.
5. **README укладывается в ~200 строк и говорит, что это, до первого `##`.**
   В ветке — да (139 строк, две фразы в строках 3–4). На опубликованном
   `master` — нет (649 строк). Пункт закроется слиянием ветки.
6. **Все относительные ссылки README резолвятся.** Да: 13 из 13 указывают на
   существующие файлы (проверено обходом ссылок).
7. **Точка входа в документацию названа в README.** Да: раздел «Документация» с
   перечислением `docs/guide/*`, `docs/DESIGN.md`, `docs/contracts/`, `docs/notes/`.
8. **Документация в репозитории, не в Wiki.** Да: `has_wiki=false`, доки —
   `docs/`. Совпадает с поведением всех двенадцати.
9. **В `docs/` есть индекс.** Нет: `docs/README.md` отсутствует, а в каталоге
   больше сорока файлов. У lazygit — единственного, кто держит доки только в
   репозитории, — `docs/README.md` есть. Роль индекса сейчас играет раздел
   README, что работает только при заходе через README.
10. **Установка — копируемая команда в README.** Частично: блок есть, но он про
    снапшот из клона (`sh scripts/release-snapshot.sh`,
    `OFFICE_INSTALL_FROM=dist sh install.sh`), потому что релизов ноль. После
    первого тега рядом с однострочником `curl … | sh` нужен второй путь
    (скачать архив из Releases и распаковать): однострочник — это 1 случай из 12,
    а ссылка на страницу релизов — норма.
11. **Платформы названы там же, где установка.** Нет: список
    `darwin/arm64`, `linux/amd64`, `linux/arm64` стоит в разделе «Требования»,
    двумя разделами ниже установки; полная матрица — в `docs/notes/install.md`.
    У k9s, lazygit и glow платформы перечислены внутри раздела установки.
12. **Рабочий первый сценарий не дальше одного клика.** Да: раздел «Первая
    задача» в README плюс `docs/guide/quickstart.md`. Это сильная сторона:
    у семи из двенадцати эталонов туториала в README нет вовсе, только ссылка.
13. **Есть изображение или каст реального запуска.** Нет: в README только
    ASCII-схема пути задачи. У 11 из 12 эталонов изображение до первого `##`
    есть, у 7 — демонстрация работы. Переносимый вариант для нас —
    скриншот или asciinema `runner ls` / прохода `runner tick`.
14. **У читателя есть названный канал для сообщения о проблеме.** Нет:
    `has_issues=false` (Issues выключены коммитом f1b2b48 «drop Issues
    (unused)»), `has_discussions=false`, чата нет. Единственный названный канал —
    приватный security-репорт в `SECURITY.md`. У всех двенадцати эталонов есть
    хотя бы один публичный канал. Это решение владельца, но в публичном README
    его стоит назвать явно, иначе отсутствие канала читается как недосмотр.
15. **`.github/ISSUE_TEMPLATE/` заведён.** Нет — и при выключенных Issues
    заводить его бессмысленно; пункт 14 заменяет этот пункт для нас.
16. **SECURITY.md есть.** Да, на `origin/master`: по-русски, с областью
    (framework, а не проект-клиент), поддерживаемыми версиями и приватным
    каналом, с честной оговоркой «сопровождающий один, SLA нет». Это
    меньшинство выборки (5 из 12), но для инструмента, который запускает агента
    с сетью и кредами и умеет сливать PR, оправдано содержанием, а не модой.
17. **CONTRIBUTING.md есть.** Нет. 8 из 12 эталонов имеют, но это артефакт
    потока контрибьюторов. Достаточным замещением выглядит абзац в README или
    ссылка на `docs/guide/development.md`, который уже описывает проверки,
    golden-кейсы и релиз.
18. **CODE_OF_CONDUCT.md есть.** Нет. 7 из 12. Без Issues и Discussions

19. **CHANGELOG ведётся.** Нет. 5 из 12 имеют `CHANGELOG.md`, ещё трое — под
