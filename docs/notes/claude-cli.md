# Claude Code CLI — рабочие заметки

Документ, к которому возвращаемся. Фиксирует проверенное поведение CLI, а не память о нём.

- Проверено: 2026-08-16, `claude` **2.1.233** (native, commit `f8d57569aaf3`), `darwin-arm64`.
- Документация переехала: `docs.claude.com/en/docs/claude-code/` отдаёт **301** на `code.claude.com/docs/en/`.

## Правило трёх источников

`claude --help` неполон. В версии 2.1.233 он не показывает флаги, которые CLI принимает и
документация описывает:

| Флаг | Есть в `--help` | Принят CLI | В документации |
|---|---|---|---|
| `--max-turns` | нет | да | да |
| `--system-prompt-file` | нет | да | да |
| `--append-system-prompt-file` | нет | да | да |

Отсюда правило: перед использованием флага сверять **три** источника — `--help`,
документацию и эмпирику. Дешёвая проверка существования флага без вызова модели:

```sh
claude --max-turns 3 --version      # неизвестный флаг → "error: unknown option"
```

## Флаги, нужные этапу 1

| Задача | Флаг | Существенное |
|---|---|---|
| промпт роли, замена | `--system-prompt-file <path>` | полностью заменяет системный промпт Claude Code |
| промпт роли, добавление | `--append-system-prompt-file <path>` | дописывает к дефолтному промпту |
| формат вывода | `--output-format json` | поля `result`, `session_id`, `total_cost_usd` + разбивка по моделям, `usage` |
| схема вывода | `--json-schema <schema>` | ответ кладётся в `structured_output`; невалидная схема → ошибка запуска |
| ограничение набора | `--tools <list>` | какие встроенные инструменты вообще доступны; `""` — выключить все |
| авто-одобрение | `--allowedTools <rules...>` | синтаксис правил: `Bash(git *)`. **Пробел перед `*` значим**: `Bash(git diff*)` поймает и `git diff-index` |
| запрет | `--disallowedTools <rules...>` | голое имя убирает инструмент из контекста; `Bash(rm *)` оставляет инструмент и режет только совпавшие вызовы |
| режим разрешений | `--permission-mode dontAsk` | запрещает всё, что не покрыто `permissions.allow`; документирован как режим для запертых CI-прогонов |
| скиллы роли | `--plugin-dir <path>` | повторяемый; каталог грузится на месте, только на эту сессию |
| изоляция конфига | `CLAUDE_CONFIG_DIR` (env) | см. ниже |
| источники настроек | `--setting-sources user,project,local` | какие слои `settings.json` вообще читать |
| настройки поверх | `--settings <file-or-json>` | перекрывает одноимённые ключи файлов; файл ≤ 2 MiB |
| доп. каталоги | `--add-dir <dirs...>` | даёт доступ к файлам, но `.claude/`-конфигурация из этих каталогов **не** подхватывается |
| лимит шагов | `--max-turns N` | только с `-p`; при достижении завершается ошибкой |
| лимит денег | `--max-budget-usd <amount>` | только с `-p` |
| привязка запуска | `--session-id <uuid>` | сюда ложится `run_id` |
| без следов сессии | `--no-session-persistence` | сессия не пишется на диск и не резюмируется |

Флага таймаута нет — таймаут держит бэкенд. При `SIGTERM` Claude Code прерывает ход,
убивает дерево процессов запущенного Bash, выполняет хуки `SessionEnd` и выходит с кодом **143**.

Коды выхода: `0` — успех, ненулевой — сбой. Невалидный флаг репортится в stderr до старта;
сбой внутри прогона (например, отсутствие авторизации) печатается как результат в stdout.

## Изоляция от хостового конфига

Без изоляции сессия `-p` грузит то же, что интерактивная: `~/.claude` (скиллы, плагины,
`CLAUDE.md`, хуки из `settings.json`) и конфигурацию проекта. Хуки проекта выполняются даже
в недоверенной папке, потому что диалог доверия в `-p` не показывается.

На машине разработчика (16.08.2026) в `~/.claude` лежало 45 скиллов, плагины, `CLAUDE.md`,
`rules/`, `agents/`, `commands/` и `settings.json` с хуками. Без изоляции smoke-тест меряет
не роль, а хостовый конфиг.

Механизмы:

- **`CLAUDE_CONFIG_DIR`** — подменяет каталог конфигурации. Проверено эмпирически:
  под подменённым каталогом `claude doctor` рапортует `Config install method: not set`,
  `Not signed in to claude.ai`, `claude.ai subscription auth not active`, а в самом каталоге
  создаются `.claude.json` и `backups/`. **Следствие: подписочный логин живёт в конфиг-каталоге,
  и полная изоляция его отключает** — см. `auth.md`.
- **`--setting-sources`** — сузить слои настроек.
- **`--bare`** — минимальный режим: пропускает автообнаружение хуков, скиллов, плагинов,
  MCP-серверов, авто-памяти и `CLAUDE.md`. Ставит `CLAUDE_CODE_SIMPLE=1`. Даёт агенту доступ
  к Bash и чтению/правке файлов. Контекст подаётся явно: `--system-prompt[-file]`,
  `--append-system-prompt[-file]`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`.
  Документация называет `--bare` рекомендуемым режимом для скриптов и обещает сделать его
  дефолтом для `-p` в будущем.

  ⚠️ **`--bare` никогда не читает OAuth и keychain** — на подписке не работает, см. `auth.md`.

## Скиллы: структура каталога для `--plugin-dir`

```
<plugin-dir>/
├── .claude-plugin/
│   └── plugin.json      # единственное обязательное поле: {"name": "..."}
├── skills/
│   └── <skill-name>/
│       └── SKILL.md
├── hooks/
│   └── hooks.json
├── agents/              # *.md
└── commands/            # *.md
```

- Компоненты лежат **рядом** с `.claude-plugin/`, а не внутри него. Внутри — только `plugin.json`.
- Если манифеста нет, компоненты автообнаруживаются в тех же местах, а именем плагина
  становится имя каталога.
- Особый случай: `SKILL.md` в корне плагина при отсутствии `skills/` грузится как единственный скилл.
- Скилл вызывается в `-p` включением `/skill-name` в текст промпта; для скилла из плагина —
  `/plugin-name:skill-name`.
- Проверка перед прогоном: `claude plugin validate <path>`.
- Проверка после старта: событие `system/init` в `stream-json` несёт `plugins` (что загрузилось)
  и `plugin_errors` (что упало, с `plugin`/`type`/`message`). Ключ `plugin_errors` отсутствует,
  когда ошибок нет, — годится как признак «скилл роли не подхватился, валим запуск».

## Хук `Stop`

Событие `Stop` срабатывает, когда агент закончил отвечать. Годится для ограждения
«не дать завершиться без валидного `result.json`».

Как заблокировать остановку:

- **код выхода 2** — остановка блокируется, разговор продолжается;
- либо код 0 и JSON в stdout:
  ```json
  {"hookSpecificOutput": {"hookEventName": "Stop", "decision": "block", "reason": "нет result.json"}}
  ```
  `reason` уходит агенту. Универсальная альтернатива — `{"continue": false, "stopReason": "..."}`.

Прочие коды — неблокирующая ошибка, остановка проходит.

Схема в `settings.json`:

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "/path/to/require-result.sh", "timeout": 600 } ] }
    ]
  }
}
```

Есть и событие `StopFailure`. Полный список событий включает `SessionStart`, `Setup`, `SessionEnd`,
`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStop` и другие.

### Окружение хука наследуется от процесса агента (этап 4, шаг 0)

Измерено, а не выведено из документации: на этом стоят ограждения этапа 4, которым
нужны ключ задачи, каталог изменения и точка отсчёта, а передать их хуку иначе,
чем окружением, нечем — аргументы задаёт адаптер, и второй адаптер повторил бы их
по-своему.

Проверка — временный хук `hooks/debug-env.sh`, кладущий `env` рядом с файлом
результата, и одноразовая роль на два шага. Прогон 2026-08-19, оба бэкенда:

| Бэкенд | Прогон | Что видит хук |
|---|---|---|
| `local` | `afd6c786`, $0.08 | все `OFFICE_*`, `CLAUDE_CONFIG_DIR`, `GIT_AUTHOR_*` |
| `sbx` | `5e6ef64f`, $0.07 | то же самое; в песочницу они едут `sbx exec --env ИМЯ=значение` |

`OFFICE_TASK_KEY` в обоих прогонах отсутствовал, и это правильно: запуск был
ручной, трекера у него нет. Пустые значения адаптер не передаёт вовсе — «нет
переменной» и «пустое значение» в шелле читаются одной формой `${VAR:-}`.

## Схема изоляции, выбранная адаптером (шаг 3)

```
CLAUDE_CONFIG_DIR=<пустой временный каталог>   # вместо ~/.claude
--setting-sources=                              # ни пользовательский слой, ни слои проекта-клиента
--settings <сгенерированный settings.json>      # разрешения и хуки роли
--append-system-prompt-file <промпт роли>       # базовые правила + роль + схема результата
--tools <имена из tools.allow + Write>          # сужает состав инструментов, а не только автоодобрение
--plugin-dir <собранный плагин>                 # только скиллы, перечисленные в роли
--permission-mode dontAsk                       # всё, чего нет в allow, запрещено
--max-turns / --session-id
--output-format stream-json --verbose           # лог наполняется по ходу работы
```

## Правила разрешений с путём (этап 3)

Понадобилось роли, которой не дают править файлы: отчитаться она всё равно обязана,
значит одному пути запись нужна. Форма правила выяснялась пробами — прямой записью
файла из `claude --print --tools Write --permission-mode dontAsk` с разным `settings.json`.

| Правило в `allow` | Запись прошла |
|---|---|
| `Write` (голое имя) | да |
| `Write(<путь>)` в любой форме | **нет** |
| `Edit(//<абсолютный путь>)` | да |
| `Edit(/<абсолютный путь>)` — одна косая | нет |
| `Edit(<относительный путь>)` | да, от каталога `settings.json` |

Два вывода, оба неочевидны:

- **путь задаётся именем `Edit`**, а не именем инструмента. Это имя семейства файловых
  инструментов, и оно покрывает `Write`; правило `Write(<путь>)` не совпадает ни с чем
  и молча не действует — отличить его от опечатки нечем;
- **абсолютный путь пишется с двумя косыми**: `//tmp/x` для `/tmp/x`. Относительный
  отсчитывается от каталога `settings.json`, а он лежит в хозяйстве запуска, а не
  в рабочей папке, — поэтому годится только абсолютный.

Запреты проверены отдельно, и они не симметричны:

| Запрет при `allow: Edit(//путь)` | Запись прошла |
|---|---|
| `deny: ["Write"]` | **нет** — точечное разрешение погибает |
| `deny: ["Edit"]` | да |
| `deny: ["NotebookEdit"]` | да |

Отсюда правило контракта роли: `tools.deny` не должен содержать голое `Write` —
`runner.LoadRole` такую роль отвергает. Чтобы роль не правила код, хватает не давать
`Write` в `allow`: этот же список задаёт состав `--tools`.

Два флага записаны неочевидно, и оба — по результатам прогонов:

- **`--setting-sources=` одним токеном**, а не `--setting-sources ""` двумя. Пустой
  элемент командной строки отвергает `sbx`: `400 Bad Request: cmd element N is empty`.
  Форма с равенством принимается разбором и сохраняет смысл. Правило шире одного флага:
  в командной строке агента не должно быть пустых аргументов.
- **`--output-format stream-json --verbose`**, а не `json`. Формат `json` отдаёт один
  блоб в самом конце, и до финала лог пуст. Поток даёт построчную ленту событий —
  видно, что агент делает прямо сейчас, — а итоговое событие `result` несёт ту же
  стоимость, длительность и число шагов.

Окружение агента собирается заново из короткого списка (`PATH`, `USER`, `SHELL`,
`TMPDIR`, `LANG`, `LC_ALL`, `TERM`) плюс `CLAUDE_CONFIG_DIR`, один выбранный кред
и личность коммитов (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`). Хостовые скиллы и настройки
не подхватываются — за это отвечает `CLAUDE_CONFIG_DIR`.

`HOME` **подменяется** на пустой каталог внутри временного хозяйства запуска. Раньше
он передавался настоящим ради `user.name`/`user.email` из `~/.gitconfig`; теперь личность
приходит переменными окружения, и основание отпало. Взамен от агента на бэкенде `local`
уезжает всё, что ищут по «~»: креды `gh`, `docker`, `aws`, `npm`.

Границей это не является, и переоценивать не надо:

- `ssh` домашний каталог берёт из `getpwuid`, а не из `HOME`, и ключи владельца машины
  находит даже с подменённым `HOME` — проверено вживую, аутентификация на GitHub прошла.
  Поэтому git отдельно получает `GIT_SSH_COMMAND` с `IdentitiesOnly=yes`,
  `IdentityAgent=none`, `IdentityFile=/dev/null`;
- абсолютный путь к чужому файлу никуда не делся: инструмент `Read` разрешён роли целиком.

Настоящая изоляция — только песочница.

**`--bare` не используется.** Он выглядел удобным, но исключает подписочную авторизацию
(«never reads OAuth credentials or the system keychain»), а его влияние на хуки, переданные
через `--settings`, документация и `--help` описывают по-разному. Изоляция через
`CLAUDE_CONFIG_DIR` даёт тот же результат, сохраняет оба пути авторизации и не зависит от
неразрешённой неоднозначности.

## Итоговое событие потока (этап 3)

Последняя строка `--output-format stream-json` — событие `type: result`. Оно несёт
`total_cost_usd`, `duration_ms` и `num_turns`; отсюда раннер берёт расход прогона.
Разбирает его адаптер: выше по стеку формат Claude Code никому не известен.

Что это за число под подпиской, из чего складывается и почему пятичасовое окно
раннеру пока не видно — `docs/notes/budgets.md`.

## Открытые вопросы

- **Семантика `--setting-sources ""`.** Пустой список принимается разбором командной строки,
  и единственное осмысленное прочтение — «не загружать ни одного слоя». Но проверено пока
  только то, что флаг принят; что он действительно отсекает `.claude/settings.json`
  проекта-клиента, покажет реальный прогон на шаге 4.
