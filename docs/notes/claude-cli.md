# Claude Code CLI — рабочие заметки

Документ, к которому возвращаемся. Фиксирует проверенное поведение CLI, а не память о нём.

- Проверено: 2026-08-16, `claude` **2.1.233** (native, commit `f8d57569aaf3`), `darwin-arm64`.
- Документация переехала: `docs.claude.com/en/docs/claude-code/` отдаёт **301** на `code.claude.com/docs/en/`.

## Правило трёх источников

`claude --help` неполон. В версии 2.1.233 он не показывает флаги, которые CLI принимает и
документация описывает:

| Флаг | Есть в `--help` | Принят CLI | В документации |
|---|---|---|---|
| `--max-turns` | нет | да | да |
| `--system-prompt-file` | нет | да | да |
| `--append-system-prompt-file` | нет | да | да |

Отсюда правило: перед использованием флага сверять **три** источника — `--help`,
документацию и эмпирику. Дешёвая проверка существования флага без вызова модели:

```sh
claude --max-turns 3 --version      # неизвестный флаг → "error: unknown option"
```

## Флаги, нужные этапу 1

| Задача | Флаг | Существенное |
|---|---|---|
| промпт роли, замена | `--system-prompt-file <path>` | полностью заменяет системный промпт Claude Code |
| промпт роли, добавление | `--append-system-prompt-file <path>` | дописывает к дефолтному промпту |
| формат вывода | `--output-format json` | поля `result`, `session_id`, `total_cost_usd` + разбивка по моделям, `usage` |
| схема вывода | `--json-schema <schema>` | ответ кладётся в `structured_output`; невалидная схема → ошибка запуска |
| ограничение набора | `--tools <list>` | какие встроенные инструменты вообще доступны; `""` — выключить все |
| авто-одобрение | `--allowedTools <rules...>` | синтаксис правил: `Bash(git *)`. **Пробел перед `*` значим**: `Bash(git diff*)` поймает и `git diff-index` |
| запрет | `--disallowedTools <rules...>` | голое имя убирает инструмент из контекста; `Bash(rm *)` оставляет инструмент и режет только совпавшие вызовы |
| режим разрешений | `--permission-mode dontAsk` | запрещает всё, что не покрыто `permissions.allow`; документирован как режим для запертых CI-прогонов |
| скиллы роли | `--plugin-dir <path>` | повторяемый; каталог грузится на месте, только на эту сессию |
| изоляция конфига | `CLAUDE_CONFIG_DIR` (env) | см. ниже |
| источники настроек | `--setting-sources user,project,local` | какие слои `settings.json` вообще читать |
| настройки поверх | `--settings <file-or-json>` | перекрывает одноимённые ключи файлов; файл ≤ 2 MiB |
| доп. каталоги | `--add-dir <dirs...>` | даёт доступ к файлам, но `.claude/`-конфигурация из этих каталогов **не** подхватывается |
| лимит шагов | `--max-turns N` | только с `-p`; при достижении завершается ошибкой |
| лимит денег | `--max-budget-usd <amount>` | только с `-p` |
| привязка запуска | `--session-id <uuid>` | сюда ложится `run_id` |
| без следов сессии | `--no-session-persistence` | сессия не пишется на диск и не резюмируется |

Флага таймаута нет — таймаут держит бэкенд. При `SIGTERM` Claude Code прерывает ход,
убивает дерево процессов запущенного Bash, выполняет хуки `SessionEnd` и выходит с кодом **143**.

Коды выхода: `0` — успех, ненулевой — сбой. Невалидный флаг репортится в stderr до старта;
сбой внутри прогона (например, отсутствие авторизации) печатается как результат в stdout.

## Изоляция от хостового конфига

Без изоляции сессия `-p` грузит то же, что интерактивная: `~/.claude` (скиллы, плагины,
`CLAUDE.md`, хуки из `settings.json`) и конфигурацию проекта. Хуки проекта выполняются даже
в недоверенной папке, потому что диалог доверия в `-p` не показывается.

На машине разработчика (16.08.2026) в `~/.claude` лежало 45 скиллов, плагины, `CLAUDE.md`,
`rules/`, `agents/`, `commands/` и `settings.json` с хуками. Без изоляции smoke-тест меряет
не роль, а хостовый конфиг.

Механизмы:

- **`CLAUDE_CONFIG_DIR`** — подменяет каталог конфигурации. Проверено эмпирически:
  под подменённым каталогом `claude doctor` рапортует `Config install method: not set`,
  `Not signed in to claude.ai`, `claude.ai subscription auth not active`, а в самом каталоге
  создаются `.claude.json` и `backups/`. **Следствие: подписочный логин живёт в конфиг-каталоге,
  и полная изоляция его отключает** — см. `auth.md`.
- **`--setting-sources`** — сузить слои настроек.
- **`--bare`** — минимальный режим: пропускает автообнаружение хуков, скиллов, плагинов,
  MCP-серверов, авто-памяти и `CLAUDE.md`. Ставит `CLAUDE_CODE_SIMPLE=1`. Даёт агенту доступ
  к Bash и чтению/правке файлов. Контекст подаётся явно: `--system-prompt[-file]`,
  `--append-system-prompt[-file]`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`.
  Документация называет `--bare` рекомендуемым режимом для скриптов и обещает сделать его
  дефолтом для `-p` в будущем.

  ⚠️ **`--bare` никогда не читает OAuth и keychain** — на подписке не работает, см. `auth.md`.

## Скиллы: структура каталога для `--plugin-dir`

```
<plugin-dir>/
├── .claude-plugin/
│   └── plugin.json      # единственное обязательное поле: {"name": "..."}
├── skills/
│   └── <skill-name>/
│       └── SKILL.md
├── hooks/
│   └── hooks.json
├── agents/              # *.md
└── commands/            # *.md
```

- Компоненты лежат **рядом** с `.claude-plugin/`, а не внутри него. Внутри — только `plugin.json`.
- Если манифеста нет, компоненты автообнаруживаются в тех же местах, а именем плагина
  становится имя каталога.
- Особый случай: `SKILL.md` в корне плагина при отсутствии `skills/` грузится как единственный скилл.
- Скилл вызывается в `-p` включением `/skill-name` в текст промпта; для скилла из плагина —
  `/plugin-name:skill-name`.
- Проверка перед прогоном: `claude plugin validate <path>`.
- Проверка после старта: событие `system/init` в `stream-json` несёт `plugins` (что загрузилось)
  и `plugin_errors` (что упало, с `plugin`/`type`/`message`). Ключ `plugin_errors` отсутствует,
  когда ошибок нет, — годится как признак «скилл роли не подхватился, валим запуск».

## Хук `Stop`

Событие `Stop` срабатывает, когда агент закончил отвечать. Годится для ограждения
«не дать завершиться без валидного `result.json`».

Как заблокировать остановку:

- **код выхода 2** — остановка блокируется, разговор продолжается;
- либо код 0 и JSON в stdout:
  ```json
  {"hookSpecificOutput": {"hookEventName": "Stop", "decision": "block", "reason": "нет result.json"}}
  ```
  `reason` уходит агенту. Универсальная альтернатива — `{"continue": false, "stopReason": "..."}`.

Прочие коды — неблокирующая ошибка, остановка проходит.

Схема в `settings.json`:

```json
{
  "hooks": {
    "Stop": [
      { "hooks": [ { "type": "command", "command": "/path/to/require-result.sh", "timeout": 600 } ] }
    ]
  }
}
```

Есть и событие `StopFailure`. Полный список событий включает `SessionStart`, `Setup`, `SessionEnd`,
`UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStop` и другие.

## Открытые вопросы

- **`--bare` и явно переданные хуки.** Документация: «skip auto-discovery of hooks».
  Локальный `--help` жёстче: «skip hooks». Работает ли `hooks` из `--settings` при `--bare` —
  проверить эмпирически на шаге 3 одним дешёвым прогоном. От ответа зависит, совместим ли
  `--bare` с ограждением `require-result.sh`.
