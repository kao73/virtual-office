# Каталог `office/` и витрина README — design

Дата: 2026-09-18. Ветка: от `master` **после** мержа PR #11 (работа опирается
на поставку офиса внутри бинарника, которую даёт #11).

## 1. Зачем

Две жалобы владельца, у которых общий корень — раскладка репозитория:

1. **Корень замусорен Go-файлами.** После #11 в корне лежат девять `.go`:
   `payload.go`, `payload_test.go`, четыре `validators_*.go`, два их теста и
   `release_config_test.go`. Они там не по небрежности: `go:embed` не умеет
   подниматься выше каталога своего пакета, а содержимое офиса — `roles/`,
   `skills/`, `hooks/`, `bootstrap/sbx-kits/`, `workflow.yaml`, `budgets.yaml`,
   оба образца — лежит в корне. Go-файлы в корне суть следствие этого.
2. **README не читается.** 649 строк: витрина, учебник, справочник по ролям,
   описание устройства, инструкция ручного запуска, список проверок и карта
   репозитория в одном файле. У сравнимых продуктов (OpenHands/Agent Canvas,
   Aider) README — 250–300 строк: над сгибом название, одна строка о продукте,
   бейджи и картинка; дальше абзац «что это», таблица возможностей со ссылками,
   quickstart, короткая архитектура и ссылки на доки. Всё прочее вынесено.

Цель — раскладка, в которой корень репозитория читается с первого взгляда,
а README отвечает на вопрос «что это и как попробовать» за минуту.

**Не цель:** менять поведение раннера, формат маркеров, протокол трекера,
контракты ролей. Ни одного изменения в том, что видит агент или трекер.
Не цель и перевод документации на английский: конвенция проекта (русский
язык документов) сохраняется, меняется только форма README.

## 2. Решения

### D1. Офис — это каталог `office/`, и пакет, который его встраивает, лежит там же

```
office/
  roles/  skills/  hooks/  sbx-kits/
  workflow.yaml  budgets.yaml  tracker.example.yaml  projects.local.example.yaml
  payload.go            package office: go:embed относительно себя
  validators/           package validators: сборки ограждения под платформы
```

`go:embed` вниз по дереву умеет, вверх — нет. Значит существует ровно одна
раскладка, в которой и корень чист, и встраивание работает: содержимое и
встраивающий его пакет живут в одном каталоге. Вариант «содержимое в `office/`,
пакет в корне» технически работает (корневой пакет может встроить `office/**`),
но не решает исходную жалобу и потому отвергнут.

Корень после переезда: `bin cmd internal docs scripts office evals install.sh
go.mod go.sum README.md CLAUDE.md AGENTS.md` и точечные файлы конвенций.

### D2. `OFFICE_CONFIG_ROOT` начинает означать буквально «каталог офиса»

Сейчас переменная указывает на корень клона, и раннер достраивает `roles/`
сам. После переезда обёртки `bin/*` выставляют `<клон>/office`, и переменная
означает то же, что `Office.Root` в режиме поставки: каталог, внутри которого
лежат `roles/`, `skills/`, `hooks/`, `workflow.yaml`, `budgets.yaml`, `sbx-kits/`.

Следствие, ради которого это стоит делать отдельно от косметики: клонов­ский
`office/` и распакованный `${OFFICE_HOME}/office/<версия>/` совпадают по
раскладке байт в байт. Сегодня они различаются — кит песочницы в клоне лежит
в `bootstrap/sbx-kits/`, в распакованном офисе в `sbx-kits/`, — и распаковка
несёт для этого специальное правило (`bootstrapPrefix` в
`internal/office/unpack.go`). Правило исчезает.

### D3. Ограждения — отдельный пакет `office/validators/`

Кросс-собранные `validate-result-<os>-<arch>` кладёт `scripts/build-validators.sh`,
встраивают четыре файла под build-тегами. Они уезжают в `office/validators/`
собственным пакетом: `office/` остаётся про содержимое офиса, `office/validators/`
— про ограждения. `internal/runner` импортирует оба.

Каталог `payload/` из корня исчезает вместе с `payload/validators/README.md`;
его роль («здесь лежат кросс-сборки, они gitignored») переходит к
`office/validators/README.md`.

### D4. Репозиторный тест конфигурации переезжает в `internal/release/`

`release_config_test.go` сверяет между собой `.goreleaser.yaml`, `install.sh`,
`scripts/build-validators.sh`, `.github/workflows/release.yml`,
`scripts/release-snapshot.sh` и имена файлов ограждений. Он не про офис и не
про ограждения — он про релизную обвязку. Место — пакет `internal/release`,
состоящий из одного теста; пути в нём считаются от `../..`.

### D5. `eval-roles` перестаёт выводить корпус кейсов из корня офиса

Сегодня `cmd/eval-roles` берёт из одного каталога и `roles/`, и `evals/`
(`officeRoot()` проверяет наличие `roles/`, затем `discoverCases` читает
`<root>/evals`). После переезда это два разных места: офис — `office/`,
корпус — `evals/` в корне репозитория. Роли берутся через
`runner.ResolveOffice` (как во всех прочих командах), корпус — от корня
репозитория, который команда определяет сама.

Это не косметика: сейчас проверка «похоже на корень офиса» служит сторожем от
молчаливого «0 cases found», и после разведения сторож нужен корпусу, а не
офису — иначе запуск не из корня снова зеленел бы на пустом множестве.

### D6. Известная цена

В режиме клона внутри `office/` лежат `payload.go`, `validators/` и тесты —
файлы, которых нет в распакованном офисе. Это видно человеку, читающему
каталог, и не видно раннеру: список `go:embed` перечисляет содержимое
поимённо, Go-файлы в поставку не попадают. Альтернативы без этой цены нет:
любая из них оставляет Go-файлы в корне.

### D7. README — витрина, руководство — в `docs/guide/`

README ужимается до ~170 строк по шаблону сравнимых продуктов. Всё, что
сегодня в нём объясняется подробно, переезжает в `docs/guide/` — раздел,
которого в проекте не было и который стоит следующим пунктом дорожной карты
(«user-guide»).

Перенос — не копирование: каждый кусок сверяется с кодом, устаревшее правится
или выбрасывается. Прежде всего это касается карты репозитория (после D1 она
другая), путей офиса и установки (изменились в #11).

## 5. Как проверяется

Переезд обязан быть наблюдаемо безобидным:

1. `go build ./... && go vet ./... && gofmt -l .` — пусто.
2. `go test ./...` — ноль упавших. Число тестов меняется ровно на один
   добавленный (пункт 6) — переезд сам по себе ни одного не создаёт и не
   удаляет; расхождение сверх этого значит, что тест потерялся при `git mv`.
   Тесты, считающие корнем репозиторий (`internal/runner/role_test.go`,
   `internal/tracker/boundary_test.go`, `internal/tracker/config_test.go`,
   `internal/adapters/claude/hook_test.go`, `internal/pipeline/pipeline_test.go`,
   `internal/runner/validator_test.go`), правятся на `office/`.
3. `sh scripts/build-validators.sh && go test -tags release ./office/...` —
   релизная сборка встраивает ограждения из нового места.
4. `sh scripts/install-test.sh` — пять сценариев, три оболочки.
5. `sh scripts/release-snapshot.sh` — живой снапшот: гейт личности отрабатывает,
   маркер на месте, `runner version` называет версию.
6. **Распакованный офис совпадает с клонов­ским.** Новый тест: распаковать
   поставку во временный каталог и сверить дерево имён с `office/` в клоне,
   исключив `payload.go`, `validators/` и `*_test.go`. Этот тест — то, ради
   чего затевался D2; без него «раскладки совпадают» остаётся обещанием.
7. `./bin/runner ls` из клона — офис берётся из `office/`, конфигурация
   печатает новый путь.
8. Ссылки в документации: ни одной битой (проверяется обходом ссылок вида
   `docs/...` и `office/...` на существование файла).

## 6. Порядок работ

Одна ветка, два этапа, один PR:

1. **Этап A — переезд.** Механический `git mv`, правка embed-директив, обёрток,
   `unpack.go`, ldflags-пути, `.gitignore`, тестов. Здесь же новый тест из
   пункта 6 проверок. Документация в этом этапе правится только там, где
   путь стал неверным (минимально: DESIGN §2.5, `docs/notes/install.md`,
   `bootstrap/sbx-kits/README.md`).
2. **Этап B — витрина.** README и `docs/guide/`; карта репозитория пишется
   сразу в новой раскладке — поэтому этап B идёт после A, а не параллельно.

Разбивать на два PR смысла нет: «Где что лежит» иначе переписывается дважды.

## 7. Риски

| Риск | Смягчение |
|---|---|
| `git mv` теряет историю файлов ролей | `git log --follow` переживает переименование; проверить на одном файле после переезда |
| Забытая ссылка на старый путь в скрипте или доке | Пункт 8 проверок + `grep` по `roles/`, `skills/`, `hooks/`, `bootstrap/sbx-kits` с исключением `docs/comet/archive` и `docs/openspec/changes/archive` |
| Смена ldflags-пути ломает подпись версии молча | Уже закрыто: `scripts/check-release-identity.sh` и тест релизной конфигурации падают, если `-X` перестанет попадать в цель |
| Переносимый в доки текст устарел и переносится как есть | Каждый файл `docs/guide/` сверяется с кодом при написании; спорное выбрасывается, а не переносится «на всякий случай» |
