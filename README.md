# virtual-office

Команда AI-агентов, ведущая разработку проекта-клиента через его трекер.
Человек участвует в фиксированных точках, а не в каждом шаге.

Пять этапов сделаны: агент в роли, конвейер вокруг него, три роли —
`analyst`, `implementer`, `reviewer` — и pull request отдельным проходом.
Механика проверена дважды на живом (не полигонном) проекте, а не только
на файловом трекере и JIRA-полигоне.

## Путь задачи

```
   человек        analyst      implementer     reviewer        человек
      │              │              │              │              │
   Backlog ──▶ Analysis ──▶ Ready ──▶ InProgress ──▶ Review ──▶ Approved ──▶ Done
                   ▲            ▲                      │  │
                   │            └─── возврат автору ───┘  │
                   └──────── возврат за планом ───────────┘
```

`Backlog` — территория человека; `Done` — единственный терминальный статус,
и попасть в него можно только через слияние pull request. Что делает каждая
роль и как считаются круги возврата — [«Роли и путь задачи»](docs/guide/roles-and-flow.md).

## Установка

Одной командой из релиза, без клона и без Go:

```sh
curl -fsSL https://github.com/kao73/virtual-office/releases/latest/download/install.sh | sh
runner init        # завести ${OFFICE_HOME} и положить образцы
runner version     # что установлено и где лежит офис
```

`install.sh` кладёт `runner` и `run-agent` в `${OFFICE_HOME:-~/.office}/bin`
и говорит, лежит ли этот путь в `PATH`.

**Тегов релиза пока нет**, и команда выше не сработает: качать с
`releases/latest` нечего. Ставится локальный снапшот — `sh
scripts/release-snapshot.sh`, затем `OFFICE_INSTALL_FROM=dist sh install.sh` —
подробности и матрица платформ — в [«Быстром старте»](docs/guide/quickstart.md).

## Первая задача

На файловом трекере `mock`, без JIRA:

```sh
runner mock add OFF-1 --status Analysis \
  --summary "Добавить hello.py" \
  --description "Создай hello.py, печатающий приветствие, и тест к нему. Закоммить."

runner tick   # аналитик пишет план
runner tick   # implementer делает
runner tick   # reviewer разбирает и одобряет
runner tick   # системный проход закрывает задачу

runner ls     # что происходит с задачей прямо сейчас
```

**Дальше — настоящие прогоны агента: они тратят подписку или деньги.**
Полный путь — от установки и заведения проекта до вопросов человеку
и того же самого против JIRA — [«Быстрый старт»](docs/guide/quickstart.md).

## Как это устроено

Решения принимает код, а не промпт: куда двигать задачу по каждому исходу,
считать ли попытку и звать ли человека — записано в `office/workflow.yaml`,
и сам агент этого файла не видит. Офис — роли, скиллы, хуки, граф, бюджеты,
кит песочницы — раннер несёт внутри бинарника и распаковывает на месте при
первом прогоне: репозиторий — фреймворк, `${OFFICE_HOME}` — инстанс.

Полностью, с обоснованием каждого решения, — [docs/DESIGN.md](docs/DESIGN.md).

## Требования

| Инструмент | Зачем |
|---|---|
| `git` | рабочая папка агента — git-репозиторий |
| `sbx` (Docker Sandboxes) | изоляция прогона, бэкенд по умолчанию |
| `claude` (Claude Code CLI) | сам агент; нужен только бэкенду `local` |
| Go 1.26+ | только для сборки из исходников |

Платформы релиза: `darwin/arm64`, `linux/amd64`, `linux/arm64`.

## Ограничения

- **Не демон.** `runner loop` не следит за собой и не перезапускается —
  расписание держит системный планировщик (launchd, systemd), не сам раннер.
- **PR по умолчанию сливает человек.** Без явного `auto_merge.enabled`
  в конфиге проекта офис не сольёт ни одного pull request сам.
- **Роль не устанавливается на машину.** Она передаётся раннером в момент
  запуска; любая машина может выполнить любую роль, ничего не храня заранее.
- **Полигон — не клиентская доска.** Файловый трекер и JIRA-полигон
  отлаживают конвейер, не трогая доску настоящего проекта; сам
  проект-подопытный до рабочего состояния не доводился — это не было целью.
